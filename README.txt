АПТЕЧКА — МОБИЛЬНЫЙ ПРОТОТИП

Открыть локально: http://127.0.0.1:8765/
Приватная публикация: https://aptechka-care-mvp.zany-cove-8800.chatgpt.site

Ключевой сценарий
1. На главном экране нажать «Распознать назначение».
2. Выбрать фото/PDF, сфотографировать документ или вставить текст.
3. Проверить оригинал и извлечённые поля каждого препарата.
4. Сверить домашний запас, точную форму, дозировку и срок годности.
5. Проверить дефицит, выбрать помощника и запустить план.

Реализовано
— OCR печатного русского и английского текста на устройстве (Tesseract.js).
— Чтение текстовых PDF, OCR сканированных PDF (PDF.js + Tesseract.js).
— До 6 файлов, 10 страниц; 10 МБ на файл, суммарно до 30 МБ.
— Извлечение названия, дозировки, формы, количества за приём,
  явно заданного времени/частоты и длительности из простых русских записей.
— Просмотр оригинальных страниц, редактирование текста и повторный разбор.
— Пустые поля для нераспознанных значений, подтверждение каждого препарата.
— Отмена обработки, обработка ошибок загрузки, ручной ввод.
— Разная длительность для препаратов, защита от пересекающихся курсов.
— Сверка запасов и срока годности, список дефицита в штуках или упаковках.
— Расписание, отметки, сигналы и общий доступ для круга заботы по ролям.

Границы
Это прототип интерфейса, не клинически валидированное медицинское изделие.
Распознавание может ошибаться. Сложные, переменные и «по необходимости»
схемы не запускаются автоматически. Поддерживаются постоянные ежедневные
схемы таблеток/капсул до 90 дней и до 8 времён в день. Если время или срок
не указаны, приложение не угадывает их. Для рукописных записей качество
не гарантировано. Структурный разбор рассчитан на простые русские записи.

Исходные файлы и распознанный текст остаются в памяти вкладки, на сервер
уходит только проверенная схема.
Библиотеки и языковые модели поставляются вместе с сайтом. Медицинские
документы не передаются внешним OCR/API. Это не защищённое медицинское
хранилище: используйте обезличенные документы для демонстрации.

Приём, отмеченный человеком, не считается объективно подтверждённым.
Покупка автоматически не оформляется. Учёт аптечки хранит один общий
остаток на точную форму/дозировку и минимальный срок этой партии.

Аккаунты и общий доступ (frontend/src/live + backend/)
Приложение работает только с бекендом: после входа данные хранятся на сервере
и общие для круга заботы: организатор, сиделка, родственники и сам подопечный
видят каждый свой экран. Подопечный получает облегчённый экран: следующий
приём, «Мне плохо», самочувствие и давление. Аптечка пополняется сканом
штрихкода или DataMatrix, дневник здоровья даёт сигнал при выходе за пороги.
Запуск всего стека: docker compose up --build (см. .env.example, backend/README.md).
Фронтенд обращается к API на своём же адресе (/api): в разработке запросы
проксирует Vite (BACKEND_URL, по умолчанию http://localhost:8080), в Docker — nginx.

Исходники: frontend/src/ (React), статика: frontend/public/.
Тесты: frontend/tests/
Проверки: cd frontend && npm test
Локальный запуск: бекенд (cd backend && ./gradlew bootRun), затем cd frontend && npm run dev

Библиотеки: frontend/public/vendor/versions.json. Основные источники:
https://github.com/naptha/tesseract.js
https://github.com/naptha/tesseract.js-core
https://github.com/mozilla/pdf.js
https://github.com/naptha/tessdata

Развёртывание на сервер 87.242.119.101, https://aptechka-beta.duckdns.org/
(deploy/ansible + .github/workflows)
CI (ci.yml) на каждую ветку и PR: тесты бекенда (Gradle, Java 25), тесты
и сборка фронтенда, проверка синтаксиса плейбука.
Deploy (deploy.yml) на push в main или вручную: те же проверки, сборка образов
backend и frontend в ghcr.io/<репозиторий>/{backend,frontend}, затем Ansible
ставит Docker на сервер, кладёт /opt/aptechka/{compose.yaml,.env} и поднимает
стек, затем пишет /etc/caddy/Caddyfile и перезагружает Caddy.
Caddy стоит на сервере без Docker (ставится вручную, плейбук его только
настраивает): принимает 80/443, сам получает и продлевает сертификат Let's
Encrypt для aptechka-beta.duckdns.org и проксирует на nginx фронтенда, который
слушает только 127.0.0.1:8765. Postgres и бекенд во внутренней сети Docker.
Запись DuckDNS должна указывать на 87.242.119.101 до первого деплоя.
Домен и порт — aptechka_domain и aptechka_frontend_port в group_vars/all.yml.
Settings → Secrets and variables → Actions:
  секреты DEPLOY_SSH_KEY — приватный ключ, публичная часть в authorized_keys на сервере;
          DEPLOY_KNOWN_HOSTS — вывод ssh-keyscan 87.242.119.101;
          POSTGRES_PASSWORD — пароль базы (после первого запуска не меняется сменой секрета);
  переменные (необязательно) DEPLOY_USER — пользователь с sudo, по умолчанию root;
          CORS_ALLOWED_ORIGINS — если фронтенд ещё и на GitHub Pages.
Вручную с локальной машины:
  cd deploy/ansible && ansible-galaxy collection install -r requirements.yml
  APTECHKA_POSTGRES_PASSWORD=... ansible-playbook playbook.yml
(для приватных образов ещё APTECHKA_REGISTRY_USERNAME и APTECHKA_REGISTRY_PASSWORD — PAT с read:packages).
